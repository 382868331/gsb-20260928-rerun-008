# 图像标注生产平台

基于 React 19 + Vite + TypeScript + zustand 的图像分割标注平台，覆盖
“批量导入 → 标注 → 提交版本 → 返工 → 导出/导入核对”的完整生产流程。

## 启动

```bash
npm run dev      # 开发服务器
npm run test     # vitest 核心逻辑测试
npm run build    # 类型检查 + 生产构建
```

## 功能与规则

- 批量导入图片（可多选），损坏/非图片文件逐个报错，不影响其他文件。
- 一个物体可画多个外轮廓；每个外轮廓可含多个孔洞（孔洞须位于所属外轮廓内）。
- 物体身份 `id` 创建后固定：修改类别、增删/拖拽轮廓与孔洞、返工再提交，
  都不会改变物体 id。
- 版本模型：
  - `draft` 草稿可任意调整；
  - 提交后版本冻结为 `submitted`，历史提交永不改变；
  - 已提交图片返工另起新版本（`basedOn` 指向上一版本），物体 id 沿用。
- 导出 JSON 只含已提交版本（草稿不导出）。
- 双人修订合并：
  - 两条修订只需存在共同祖先版本：沿 `basedOn`/`mergeOf` 来源链核对，
    连续返工的多代链（如先拆分再局部合并）可直接合并，无需压缩中间提交；
  - 类别、外轮廓、孔洞按物体 id / 轮廓 id / 孔洞 id 对应做三方合并，
    互不冲突的修改自动一起保留；
  - 同一部分的不同修改（含“一边删除物体、另一边改它的孔洞”）列为冲突，
    用户查看基线/A/B 前后差异逐项确认，可单独撤回某项确认；
  - 合并会话自动持久化并随项目导出，重新导入后中途关闭的比较可继续；
  - 完成合并生成一个新的已提交版本，`mergeOf` 记录基线与两条修订来源，
    物体 id 保持稳定，历史提交不被改写。
  - 多分支来源的最小冲突规划：沿拆分/合并（含连续拆分后交叉合并、三代共同
    来源）枚举候选——哪些可共同采用、哪些会把同一来源矛盾分配到重叠物体；
    共享祖先汇聚到同一物体时不重复算成两个独立物体，独立来源物体无法靠删除
    消除冲突，在每份完整方案中都强制保留；
  - 可为来源物体指定必须保留的类别或同组约束，规划给出按剩余冲突排序的可比较
    方案及无法同时满足的最小决定集合；批准整份或一部分候选时写入依赖闭合，
    撤回关系决定会重开其片段决定并提示受影响物体与候选。
- 导入时逐图处理（逐图事务）：
  - 缺少图片数据、记录损坏、轮廓/孔洞几何非法、轮廓交叉、未知类别等问题
    全部定位到 图片 / 版本 / 物体 / 轮廓；
  - 有问题的图片整图拒绝，**不会**覆盖该图或其他图片已提交的结果；
  - 校验通过的版本按版本号合并，已有同版本号不被覆盖，仅追加缺失版本。

## 代码结构

- `src/types.ts`：数据模型（图片、版本、物体、轮廓、孔洞、导入问题）。
- `src/core/geometry.ts`：多边形面积、点包含、线段相交、自交/交叉检测。
- `src/core/validation.ts`：单版本全部可定位校验。
- `src/core/versioning.ts`：物体身份、草稿/提交/返工/丢弃的版本规则。
- `src/core/exchange.ts`：导出与逐图事务导入。
- `src/core/merge.ts`：三方合并（diff、冲突检测、裁决落地）。
- `src/core/planning.ts`：多分支来源候选枚举、冲突/约束求解、方案批准与撤回影响。
- `src/store.ts`：zustand 状态 + localStorage 持久化。
- `src/components/`：工具栏、图片列表、SVG 标注画布、物体面板、版本栏。
